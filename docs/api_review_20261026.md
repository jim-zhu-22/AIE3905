# API 封装评价与改进 · v0.1 → v0.2

v0.1 是可以演示的“已有成果发布原型”，已具备基本接口和模型适配入口。它还缺少稳定组内联调所需的输入约束、错误追踪、失败清理与复现验证，不能据此声称真实模型和 Docker 已跑通。本轮针对可确认的问题完成了代码修复。

## 发现的问题与已落地改进

| 原有不足 | 实际影响 | v0.2 改进 |
| --- | --- | --- |
| 只接受 Base64 | 同学需自己写转换代码，试用不方便 | 保留旧接口，增加 multipart 直接上传，演示页和文档均可选文件 |
| 结果直接写进正式目录 | 拷贝、磁盘写入或导出失败时会留下半包，且同名导入难以重试 | 隐藏临时目录写入，重新验证后原子发布；失败回滚，同名保护 |
| 长度限制发生在 JSON 解码后 | 大请求已被读取和解析，字段限制无法约束整个请求体 | 解析前检查 Content-Length 与实际分块长度，总请求限制 22 MiB |
| 深度为任意字典；结果校验分散 | 单位比例错误、实例数与列表不一致、框越界等问题难以统一发现 | 独立结构定义，校验深度尺寸、正比例尺、有限分数、数量状态、编号及路径唯一性 |
| 模型返回错误 mask 仍可能导出 | mask 尺寸或像素值不符合下游假设 | 导出前校验形状和二值值；发布前验证 PNG、JPEG、框和 mask 一致性 |
| 422、404、500 错误结构不同 | 调用方需分别解析，参数错误还可能回显大幅输入 | 统一 error/code/message/request_id/fields，字段错误只返回必要原因 |
| 没有贯穿请求的编号 | 页面报错后难以对应服务日志 | 所有响应返回 X-Request-ID，模型错误和请求日志使用相同编号 |
| /ready 只判断模型 | archive 正常运行时仍返回未就绪，部署检查含义不清 | 按模式检查；能力接口明确区分已有结果可读与新图片推理可用 |
| 推理成功后缺少查询入口 | 调用方丢失响应后无法按编号查询 | 新增 GET /v1/runs/{run_id}，读取已完成持久化结果 |
| 只固定直接依赖 | 换环境可能安装不同间接依赖 | 冻结 16 个 API 运行依赖，另行检查不继承现有包的新环境 |
| Docker 默认 root，检查仅存活 | 启动成功不代表已挂载可用样例 | 非 root、只读根文件系统、明确只读数据挂载、就绪健康检查和单 worker |
| 一份文件承担所有职责 | 修改存储或图像逻辑容易影响路由 | 分离 schemas、images、storage、errors 与接口适配 |

## 验证范围

- 23 项代码测试通过，覆盖上传、失败回滚、并发、参数及结果约束、错误追踪、只读启动与结果查询。模型使用合成测试替身，仅证明接口逻辑。
- 52 项实际 HTTP 检查通过，包含 34 张样例 mask 的下载、尺寸、二值像素和整数框核对，以及两种推理入口在未启用时的明确拒绝。
- 不继承系统包的全新 Python 3.12 环境按 requirements.lock 安装成功，同样通过 52 项实际 HTTP 检查；记录保存在 output/api_clean_verification_v02.json。这项验证不能代替 Linux Docker 测试。
- 测试脚本即使失败也会保存 complete=false 和已执行记录，避免沿用旧的成功结论。

## 兼容性变化

Base64 请求地址、成功输出主要字段和样例地址保留。错误响应由 v0.1 的 detail 改为统一 error；/ready 改为按服务模式判断。调用方应以 /v1/capabilities 的 new_inference_available 判断是否能提交新图，不能仅凭 /ready 的 200 推断模型可用。

## 仍需实际验证

1. 当前没有 PyTorch 模型环境，真实 DINO/SAM 推理、设备资源占用及耗时仍未验证。这是继续联调的首要任务。
2. 当前没有 Docker，Dockerfile/Compose 只有代码与配置，未在 Linux 容器中构建运行。Windows 新环境验证不能代替这项验证。
3. 本版本是单进程同步推理接口，繁忙时拒绝新请求并给出重试提示。若后续需要长任务排队或断线恢复，应再引入任务队列与状态持久化。
4. 输出数量不能证明预测准确性；深度像素、材质、几何和完整 /v1/perceive 仍未接入。

实现参考：[FastAPI 文件与表单](https://fastapi.tiangolo.com/tutorial/request-forms-and-files/)、[统一错误处理](https://fastapi.tiangolo.com/tutorial/handling-errors/)、[Docker Compose 服务配置](https://docs.docker.com/reference/compose-file/services/)。
